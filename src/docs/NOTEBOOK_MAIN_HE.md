## 0. Setup + טעינת המודל

שני תאים:

1. **בדיקת תלויות** - עובר על כל הספריות שהמחברת דורשת (opencv,
   numpy, pandas, matplotlib, Pillow, ultralytics, ipywidgets,
   urllib3), מתקין את מה שחסר ומדפיס את הגרסאות שהותקנו. בטוח
   להריץ שוב - ריצות נוספות מדפיסות רק את הגרסאות.
2. **טעינת המודל** - מייבא את פונקציות ה-CV מ-`src.app.detect_core`
   ואת קטלוג המצלמות מ-`src.app.cameras`, טוען את
   `yolo26m.pt` (או `yolo26x.pt` אחרי השדרוג) פעם אחת ושומר על
   ה-model handle לשימוש חוזר. הטעינה מזהה אוטומטית `_openvino_model/`
   ליד ה-`.pt` ומעדיפה אותו על CPU.

אם התא הראשון התקין ספרייה חדשה, יש להפעיל את ה-kernel מחדש
(Kernel > Restart) לפני שממשיכים.

<a id="תפריט-המצלמות"></a>

## תפריט המצלמות

- **תא הרשימה** - קורא ל-`active_cameras()`, מדפיס טבלה ממוספרת של
  כל המצלמות שיש להן URL תקף (בפרויקט הנוכחי - תשע מצלמות
  תאילנדיות). המספור הוא 1-based ומתאם לרשימה שמופיעה.
- **תא הבחירה** - מכיל משתנה `PICK = 1`. שינוי המספר בוחר מצלמה
  אחרת מהרשימה. הרשימה נשמרת ב-`SELECTED_CAMS` (רשימה של מזהה
  יחיד לפי מגבלת single-camera של הפרויקט הזה).
- **תא הווידוא** - מדפיס אישור בשורה אחת עם מזהה המצלמה + השם.

<a id="1-פענוח-המצלמה-שנבחרה"></a>

## 1. פענוח המצלמה שנבחרה

אחרי שהמצלמה נבחרה, התא הזה קורא ל-`resolve_stream(cam)` ומדפיס את
כתובת ה-HLS שהמנוע יגיע אליה. מצלמות `youtube` דורשות `yt-dlp` -
אם הוא נחסם ע"י YouTube bot check, הכתובת לא תיפתר (הפוסט-מורטם:
ה-iframe בדשבורד עדיין ינגן את הוידיאו, backend לא יוכל להריץ
detection). ראה `src/docs/PROJECT_GUIDE_HE.md` על יצוא cookies.

<a id="2-בדיקת-פריים-בודד"></a>

## 2. בדיקת פריים בודד

מוודא שהזרם מפוענח וש-YOLO רואה תוכן לפני שאוגרים משהו:

1. `grab_frame(stream_url)` שולף פריים אחד.
2. `detect_and_count(model, frame)` מריץ את המודל ומחזיר מילון
   מהצורה `{person: N, vehicles: M}`.
3. `model.predict(...).plot()` מצייר תיבות + labels על עותק של
   הפריים ומציג אותו ב-`matplotlib`. זה הבדיקה הראשונה
   שהזרם עובד וש-YOLO מזהה משהו סביר.

אם הפריים חוזר `None`, המצלמה חסומה גיאוגרפית או שהזרם מת - בחר
מצלמה אחרת.

<a id="3-סדרת-ספירת-אנשים-בזמן"></a>

## 3. סדרת ספירת אנשים בזמן

`footfall_series(...)` דוגם את המצלמה כל 10-20 שניות במשך דקה בערך,
מריץ ספירה לכל פריים, וכותב את התוצאה ל-CSV תחת
`src/data/footfall_<cam>.csv`. זו אותה הלוגיקה של הקולקטור, פשוט
בחלון קצר. כשל של פריים אחד מסומן כ-NaN ולא עוצר את הסדרה.

<a id="4-אנומליות-ופרופיל-שעות-עומס"></a>

## 4. אנומליות ופרופיל שעות עומס

- **אנומליה** - `flag_anomalies(...)` משתמש ב-z-score עם חלון גלגלת
  מבוסס median + MAD (`spread = mad.clip(lower=1.0)`). הבחירה במדדים
  robust ולא ב-mean/std מונעת מ-outliers חדשים לזייף את ה-baseline
  ולהסתיר את האנומליה הבאה. אנומליה = `z > 3.5` ושינוי מוחלט של
  לפחות 3 ספירות.
- **פרופיל שעות עומס** - קיבוץ הסדרה לפי `hour` וממוצע. שני
  גרפים זה לצד זה: סדרה בזמן עם נקודות אנומליה מסומנות באדום, ומספרי
  אנשים ממוצעים לפי שעה.

<a id="5-שהייה-ועצירות-ממושכות"></a>

## 5. שהייה ועצירות ממושכות

`dwell_analysis(...)` דוגם את הזרם ב-3 FPS למשך 30-60 שניות ומריץ
`model.track(persist=True, tracker='bytetrack.yaml', ...)`. לכל
טרק נשמר מספר הפריימים שראינו אותו וכל המסלול של מרכזי התיבות.

הפלט הוא DataFrame:

| שדה          | משמעות |
| ------------ | ------ |
| `track_id`   | מזהה שנשאר יציב לאורך החלון. |
| `class`      | person / car / motorcycle / ... |
| `dwell_s`    | כמה שניות ראינו את הטרק (הזמן שהופיע במסך). |
| `movement_px` | תזוזה מקסימלית של המרכז לאורך החלון. |

הבחירה של `stride = max(1, round(25 / target_fps))` חשובה: זרם רץ
בערך ב-25 FPS, אז אנחנו צריכים לדלג frames כדי לדגום את החלון
בפריסה הזמנית האמיתית. בלי dilog, החלון של דקה מתקצר לפחות מ-4
שניות.

**עצירות ממושכות**: התא הבא מסמן טרקים שנשארו הרבה זמן (25s לאדם,
40s לרכב) עם תזוזה קטנה (`movement_px <= 60`). זה מקור מדד ה-linger
של הסקירה העסקית.

<a id="5b-re-identification"></a>

## 5b. Re-identification

`ReidStore` (`src/app/reid.py`) שומר חתימה של כל טרק שמתגלה על
מצלמה. החתימה היא היסטוגרמת HSV 8×8×8 עם מיסוך של V<30 (מנטרל את
הצבע הצהוב של תאורת סודיום בלילה), plus יחס גובה-רוחב + שטח
מנורמל. סה"כ 514 מימדים, נורמליזציה L2, השוואה קוסינוסית.

**לולאת הדגימה** - קוראים לפריים, מפעילים zorbing עם `detect_with_boxes`,
עוברים על התיבות ומזרימים לרישום. `results = reid.update_from_frame(...)`
מחזיר לכל טרק:

- `is_new = True` אם החתימה לא התאימה לאף רשומה קיימת (>= threshold=0.92).
- `is_new = False` אם התאימה - אז `entity_id` מקבל +1 sighting.

**מגבלה כנה** - HSV histogram עובד יפה ביום (בגדים בצבעים שונים =
היסטוגרמות שונות). בלילה סודיום, כל השטח נעשה צהוב-כתום ומרבית
ההיסטוגרמות מתלכדות → merges שגויים. הפתרון production הוא להחליף
את `embed_crop()` ב-OSNet ONNX forward pass; שאר `reid.py` נשאר.

<a id="6-ציון-האם-שווה-לפתוח-פה-עסק"></a>

## 6. ציון "האם שווה לפתוח פה עסק?"

`business_score(...)` שולש שלושה אותות למספר 0-100 יחיד:

- **Volume** - median של סדרת ה-footfall. הביקוש הגולמי.
- **Linger** - אחוז האנשים שנשארים לפחות 25 שניות (המקדם הסטטי
  בתא). איכות התנועה (מי שעוצר, לא רק חולף).
- **Consistency** - `max(0, 1 - CV)` על סדרת ה-footfall. תנועה
  יציבה עדיפה על תנועה חדה.

המשקלות ברירת המחדל `(0.5, 0.3, 0.2)` נוטים לכיוון volume; בית קפה
ירצה משקל linger גבוה יותר, קיוסק ירצה volume דומיננטי.

**הגנות שוליות** - סדרה ריקה או all-NaN מחזירה `score = None` +
הודעת "insufficient data" במקום 0.0 (בעבר NaN חילץ ל-0.0 ונקרא כמו
"מקום גרוע" במקום "אין מספיק דגימות").

<a id="7-הדשבורד-החי-המוטמע"></a>

## 7. הדשבורד החי המוטמע

התא הזה כותב `src/web/local_grid.json` עם המצלמה הבודדת שנבחרה,
מריץ `bind(PORT=8000)` ב-thread רקע, ומטמיע `IFrame` שמצביע ל-
`http://localhost:8000/?cam=<id>`. אותה מצלמה שבחרנו בפייתון
מתחילה להיטען בפנל הדשבורד בתוך המחברת.

הכל מקומי - אין כתיבה לענן. אם הפורט 8000 תפוס, יש לשחרר אותו לפני
שמריצים (או להחליף את `PORT`).

<a id="8-השוואה-בין-מספר-מצלמות"></a>

## 8. השוואה בין מספר מצלמות

במצב single-camera של הפרויקט הזה, התא הזה משווה בעצם רק בין המצלמה
שנבחרה לעצמה - נשאר כתא-שלד להרחבה במקרה שתחליט להשוות מספר מיקומים
ולדרג אותם לפי median פעילות.

<a id="9-סיכום-ריצה-חי"></a>

## 9. סיכום ריצה חי

מרכז את כל מה שנאסף בריצה הנוכחית לבלוק אחד: אנומליות שסומנו, סיכום
re-ID, וגרף אחד עם הסדרה של אנשים + רכבים לאורך הריצה + נקודות
אדומות במקומות האנומליות. הבלוק בטוח אפילו אם חלק מהמשתנים לא
קיימים (המחברת עדיין לא הריצה כל תא).

<a id="10-כיול-דיוק-המודל"></a>

## 10. כיול דיוק המודל

שלושה תת-סעיפים:

- **10a - Capture** - שולף `FRAMES_PER_CAM = 6` פריימים מהמצלמה,
  מריץ עליהם zorbing בשני גדלים (`imgsz = 640` ו-`imgsz = 960`)
  לצורך השוואה, ושומר את התוצאה ב-`src/data/calibration/predictions.json`.
  לצד כל פריים נשמר גם עותק מסומן `<stem>_annotated.jpg` שמראה מה
  המודל ראה.
- **10b - Label** (interactive) - עובר על כל פריים, מציג את התמונה
  המסומנת ומחכה שתכניס את הספירה האמיתית `people,vehicles` (מפרידים
  בפסיק). Enter מדלג פריים, `q` עוצר. יש דגל `RUN_LABELING = False`
  כברירת מחדל כדי שהתא לא יעצור את Run All.
- **10c - Report** - מ-`labeled.json` מחשב MAE + bias לכל
  imgsz ולכל מצלמה. מסקנות:
  - `bias < 0` = המודל חסר. אפשר להוריד את הסף `conf` של המצלמה
    ב-`app/cameras.py` (למשל `"conf": 0.25`).
  - `bias > 0` = המודל מקשקש. תעלה את ה-`conf`.
  - `MAE@960 < MAE@640` (טיפוסי בשוטים רחבים) = תשאיר imgsz=960
    כברירת מחדל.

הכיול מוזן חזרה למערכת דרך `data/per_camera_conf.json` -
`_merge_per_camera_conf()` ב-`cameras.py` קורא את הקובץ בזמן ייבוא
ומדביק את ה-conf המכויל לרשומת המצלמה.
